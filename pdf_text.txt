2. Đề tài 
●​ Tên đề tài: Workspace Hub 
●​ Problem Statement: Người dùng phải mở nhiều ứng dụng (Gmail, Calendar, 
Drive,…) để theo dõi cùng một dự án. Không có cách gom nhóm theo context, khó 
chia sẻ view tổng thể cho đồng đội, thiếu dashboard quản trị. 
●​ Mô tả: Ứng dụng web kết nối nhiều hệ sinh thái để gom nhóm email, sự kiện, file, 
ticket, note vào một nơi duy nhất. Người dùng có thể quản lý theo Folder context 
(Dự án, Khách hàng, Chủ đề) với giao diện Kanban drag-drop. 
Đối tượng: 
●​ Người dùng cá nhân: cần gom dữ liệu từ nhiều dịch vụ vào một nơi để quản lý 
công việc. 
●​ Nhóm làm việc: muốn chia sẻ Folder, phối hợp dự án nhanh gọn. 
●​ Quản trị viên hệ thống: giám sát, quản lý user và đảm bảo bảo mật.

4. Phân tích bài toán 
User Roles: 
●​ Admin: Quản trị hệ thống, quản lý user, khóa/mở account, xem thống kê sync, 
force-disconnect integration. 
●​ User: Người dùng mặc định, có thể kết nối dịch vụ, tạo Folder, kéo thả Item, chia 
sẻ Folder với quyền Viewer. 
External Dependencies 
Hệ thống tích hợp với Google (Gmail, Calendar, Drive,...). 
Functional Requirements: 
●​ Kết nối OAuth với Google. 
●​ Đồng bộ email, sự kiện, file, ticket, note thành Item 
 
 
●​ Tạo Folder, drag-drop Item vào Folder (Kanban view) 
●​ Compose & Schedule Send email 
●​ Important Contact (đánh dấu email/ticket quan trọng) 
●​ Folder Share (Viewer-only) 
●​ Admin Dashboard quản trị user 
●​ Search & Filter Items: Lọc nâng cao theo nguồn, trạng thái, folder, tag 
●​ Respond to Share Invitation: Chấp nhận hoặc từ chối lời mời chia sẻ Folder 
●​ Notification Management: Xem và đánh dấu đã đọc thông báo trong hệ thống 
Non-functional Requirements: 
●​ Bảo mật: JWT + RBAC + Resource-based Authorization 
●​ Khả năng mở rộng: Thiết kế polymorphic Item, hỗ trợ nhiều nguồn dữ liệu 
●​ Privacy: Viewer chỉ thấy metadata, không thấy body email/file

Workspace Hub — Mô tả Database 
Quan hệ tổng quan  
Users 1──n OAuthConnections 1──n ServiceConnections 1──n Items 
Users 1──n Folders 1──n ItemFolders n──1 Items 
Users 1──n Tags 1──n TagAssignments n──1 Items

Users 1──n Notifications 
Integrations 1──n OAuthConnections 
Folders 1──n FolderShares ──n──1 Users (SharedWithUserId / CreatedByUserId) 
 
Cardinality chính: 
●​
Users là gốc của hầu hết bảng (1-n). 
●​
Items ↔ Folders: nhiều-nhiều qua ItemFolders. 
●​
Items ↔ Tags: nhiều-nhiều qua TagAssignments. 
●​
OAuthConnection → ServiceConnection: 1 grant Google bật nhiều service (Gmail/GCal/Drive). 
●​
Item → ServiceConnection: n-1, nullable (Note không thuộc service nào).

API Design 
 
 
Workspace Hub — API Design  
Quy ước chung 
●​
Base URL: https://api.workspacehub.app (prod) · https://localhost:5001 (dev) 
●​
Authentication: JWT Bearer, header Authorization: Bearer <token>. Claim chính: sub (UserId), 
email, role. 
●​
Content-Type: application/json cho mọi request/response (trừ upload file). 
●​
DateTime: ISO 8601 UTC (2026-05-25T14:30:00Z). 
●​
Pagination: ?page=1&limit=20. Default limit=20, max 100. 
●​
Response collection (quy ước chuẩn hoá): 
○​
List có thể tăng lớn (items, users, notifications, scheduled-emails) → envelope { "items": [...], 
"total": N, "page": 1, "limit": 20 }. 
○​
List giới hạn nhỏ, không phân trang (integrations, connections, folders, tags, shares) → trả 
thẳng array [...]. 
●​
Error wrapper: xem Phụ lục error format.

1.1. Đăng ký

1.2. Đăng nhập 
POST /api/auth/login · Auth: không cần 
Request: { "email": "vy@gmail.com", "password": "MySecure123!" } 
Response 200: 
{ "accessToken": "eyJhbGc...", "expiresIn": 3600, "user": { "id": "uuid", "email": "vy@gmail.com", 
"fullName": "Vy Cường", "role": "User" } } 
 
Status: 200, 400 (sai format), 401 (sai thông tin / account bị khoá).

POST /api/auth/logout · Auth: Bearer

dùng expiresIn ngắn hoặc blacklist.)
